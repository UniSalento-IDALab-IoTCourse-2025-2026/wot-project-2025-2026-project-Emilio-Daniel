# E9 - Task e test cognitivi nella dashboard medico

## Obiettivo

Il compito E9 completa la parte della dashboard medico dedicata all'invio e alla
lettura dei task/test destinati al paziente. La schermata deve permettere al medico di
creare un'attivita', seguirne lo stato e consultare il risultato quando l'app paziente lo
invia al backend.

La logica resta coerente con il backend realizzato da Daniel nel compito D9:

```text
medico crea task
-> backend salva task
-> app paziente completa task
-> backend salva risultato
-> WebSocket invia evento task_completed
-> dashboard aggiorna elenco e dettaglio
```

## Cosa e' stato fatto

### Dashboard medico

Nella sezione `Attivita` della dashboard sono stati aggiunti:

- elenco task con stati `created`, `sent`, `seen`, `completed`, `expired` e `cancelled`;
- riepilogo di task totali, aperti, completati e scaduti;
- filtro per stato;
- form di creazione con tipo test, priorita', scadenza, istruzioni e nota medico;
- tre template iniziali:
  - check-in benessere;
  - PHQ-2 in forma dimostrativa;
  - test cognitivo breve dimostrativo;
- template clinici assistiti per:
  - MMSE;
  - MoCA;
- pannello dettaglio del task selezionato;
- visualizzazione di score previsto, destinatario, scadenza, completamento e durata;
- visualizzazione delle risposte ricevute quando il backend restituisce il risultato;
- salvataggio di una nota medico collegata al task/risultato;
- annullamento di task non ancora completati;
- refresh automatico della lista quando arrivano eventi WebSocket `task_completed`,
  `task_cancelled` o `task_updated`.

### Backend

Per rendere la dashboard realmente leggibile e non solo predisposta, sono stati aggiunti:

- risultato piu' recente dentro la risposta `GET /api/v1/patients/{patient_id}/tasks`;
- endpoint `PATCH /api/v1/tasks/{task_id}/medical-note` per aggiornare la nota medico;
- audit dell'aggiornamento nota;
- evento interno `task_updated` dopo il salvataggio della nota.

## Nota su PHQ-2 e licenze

Il PHQ-2 e' stato inserito come template dimostrativo per il prototipo universitario.
MMSE e MoCA sono stati integrati come task di somministrazione assistita, senza copiare
nel codice le domande ufficiali.

Per MMSE e MoCA la dashboard invia solo:

- titolo del test;
- istruzioni per usare materiale ufficiale autorizzato;
- campo per punteggio totale riportato dal modulo ufficiale;
- campo note sulle aree osservate, senza trascrivere item protetti.

Prima di usare questi test in una demo formale o in documentazione definitiva bisogna
chiedere al docente quali test possono essere riprodotti e con quali condizioni di
licenza. Per la versione finale, l'eventuale modulo ufficiale deve restare separato e
autorizzato.

Per questo motivo nel file `CompitiDivisi.md` il punto relativo alla verifica con il
docente resta volutamente aperto.

## Come testare

### 1. Avviare backend e dashboard

Backend:

```powershell
cd cloud\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8080
```

Dashboard:

```powershell
cd Dashboard
npm run dev
```

Login medico demo:

```text
medico.demo@localhost.invalid
provaprova
```

### 2. Creare un task

Aprire la sezione `Attivita`, premere `Nuova attivita` e provare:

- check-in benessere;
- PHQ-2;
- test cognitivo breve.
- MMSE;
- MoCA.

Verificare che il task compaia in elenco con priorita', stato, scadenza e istruzioni.
Per MMSE e MoCA verificare che non vengano mostrate domande ufficiali, ma solo campi di
somministrazione assistita e raccolta punteggio.

### 3. Verificare completamento e realtime

Quando l'app paziente inviera' un risultato a:

```text
POST /api/v1/tasks/{task_id}/results
```

la dashboard deve aggiornarsi tramite WebSocket e mostrare:

- data di completamento;
- durata;
- risposte;
- score se il backend puo' calcolarlo;
- eventuale nota del paziente.

### 4. Salvare nota medico

Nel dettaglio del task inserire una nota nel campo `Nota medico sul risultato` e salvarla.
La nota viene inviata al backend tramite:

```text
PATCH /api/v1/tasks/{task_id}/medical-note
```

### 5. Annullare un task

Per task non ancora completati, usare `Annulla task`. Il backend aggiorna lo stato a
`cancelled` e la dashboard ricarica l'elenco.
