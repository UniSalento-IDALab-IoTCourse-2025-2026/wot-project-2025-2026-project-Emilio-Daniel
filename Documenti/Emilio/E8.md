# E8 - Stato tecnico del sistema

## Obiettivo

Il compito E8 completa la pagina `Sistema` della dashboard medico. L'obiettivo non e'
mostrare log grezzi, ma dare al medico e a chi gestisce l'installazione una lettura
rapida dello stato tecnico:

```text
Raspberry Pi 5
-> ultimo ciclo Edge
-> sensori BLE / wearable / Google Health
-> qualita' dati
-> MQTT e coda locale
-> WebSocket dashboard
-> warning temporanei e guasti persistenti
```

La pagina resta coerente con il backend di Daniel: usa l'endpoint reale
`GET /api/v1/patients/{patient_id}/system-status`.

## Cosa e' stato fatto

- La vista `Sistema` della dashboard ora mostra uno stato generale del sistema:
  `Operativo`, `Attenzione tecnica` oppure `Guasto da verificare`.
- Vengono mostrati ultimo contatto del Raspberry, ultimo ciclo Edge, durata della
  finestra e intervallo osservato.
- Vengono mostrati stato BLE, stanza corrente, campioni raccolti nell'ultimo ciclo,
  wearable presente/assente, batteria wearable e ultimo dato disponibile.
- Viene mostrato lo stato Google Health con feature disponibili e ultimo dato
  sincronizzato.
- Gli errori OAuth vengono mostrati solo come messaggi ripuliti. Token, refresh token,
  password, `client_secret` e header `Authorization` non vengono mai mostrati.
- Viene mostrato lo stato MQTT: tentativi, pubblicazioni riuscite, messaggi in coda e
  messaggi di errore ripuliti.
- La pagina separa warning temporanei e guasti persistenti.
- Gli eventi WebSocket vengono tradotti in italiano leggibile.
- Il backend e' stato esteso per esporre nella risposta `system-status` anche i dettagli
  tecnici derivati dall'ultimo `edge/status`.

## Test da provare

Backend:

```powershell
cd cloud\backend
.\.venv\Scripts\python.exe -m pytest tests\test_d5_api.py
```

Dashboard:

```powershell
cd Dashboard
npm run build
```

Test manuale:

```powershell
$login = Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8080/api/v1/auth/login" `
  -ContentType "application/json" `
  -Body '{"email":"medico.demo@localhost.invalid","password":"PASSWORD_DEMO"}'

$headers = @{ Authorization = "Bearer $($login.access_token)" }

Invoke-RestMethod `
  "http://127.0.0.1:8080/api/v1/patients/patient-001/system-status" `
  -Headers $headers
```

Nella dashboard:

```text
1. Aprire http://127.0.0.1:5173
2. Effettuare il login medico.
3. Entrare nel tab Sistema.
4. Verificare ultimo ciclo, sensori, MQTT, OAuth e warning/guasti.
5. Spegnere temporaneamente MQTT o Edge e verificare che la UI lo mostri come problema tecnico.
```

## Nota importante

Questa vista non produce diagnosi e non interpreta clinicamente un guasto tecnico. Serve
a distinguere se un problema nasce dal comportamento osservato o da una parte del sistema
che non sta inviando dati.
