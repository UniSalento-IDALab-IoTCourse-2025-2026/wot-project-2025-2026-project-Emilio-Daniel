# E3 - Struttura della dashboard medico web

Questo documento riassume il lavoro fatto per il punto E3: creare una prima dashboard
medico React, navigabile e collegata al mock backend E2, pronta a passare al backend reale
di Daniel cambiando solo configurazione.

## Obiettivo

La dashboard deve permettere al medico di aprire il sistema e lavorare gia' con:

```text
login
lista pazienti
dettaglio paziente
alert
task
stato sistema
eventi WebSocket
```

La UI non deve presentare diagnosi automatiche. Tutti i testi parlano di triage,
priorita' e revisione clinica.

## Configurazione

Il frontend legge solo variabili `VITE_*`.

Mock locale:

```text
VITE_API_BASE_URL=http://127.0.0.1:8090/api/v1
VITE_WS_BASE_URL=ws://127.0.0.1:8090/ws/v1
VITE_DATA_SOURCE=mock
```

Backend reale:

```text
VITE_API_BASE_URL=https://host-backend/api/v1
VITE_WS_BASE_URL=wss://host-backend/ws/v1
VITE_DATA_SOURCE=real
```

Quando Daniel espone le API reali, non bisogna riscrivere la dashboard: basta cambiare
URL.

## Funzioni implementate

### Login e sessione

La dashboard chiama:

```text
POST /api/v1/auth/login
```

La sessione viene salvata in `localStorage`, con logout esplicito.

### Client REST centralizzato

File:

```text
Dashboard/src/api/client.js
```

Contiene le chiamate principali: login, pazienti, stato corrente, finestre, decisioni,
alert, task, stato sistema, presa in carico, risoluzione e creazione task.

Gli errori vengono normalizzati in:

```text
Dashboard/src/api/errors.js
```

### WebSocket centralizzato

File:

```text
Dashboard/src/api/realtime.js
```

La dashboard si collega a:

```text
WS /ws/v1/patients/{patient_id}
```

Se la connessione cade, prova a riconnettersi dopo pochi secondi.

### Navigazione

La UI include:

```text
Paziente
Alert
Task
Sistema
```

La lista pazienti resta nella sidebar e ordina per severita'.

### Stati gestiti

Sono gestiti:

- caricamento;
- backend non raggiungibile;
- permessi insufficienti;
- sessione scaduta;
- nessun dato;
- dati obsoleti;
- WebSocket in connessione, attivo, errore o riconnessione.

### Responsive e accessibilita'

La dashboard e' pensata per desktop e tablet:

- layout a sidebar su desktop;
- layout a singola colonna su schermi piccoli;
- bottoni con icone;
- focus visibile;
- tabelle con scroll orizzontale quando serve;
- colori con testo esplicito, non solo semaforo.

## Avvio

Avviare prima il mock backend:

```powershell
cd mock_backend
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8090
```

Poi la dashboard:

```powershell
cd Dashboard
npm install
npm run dev
```

Aprire:

```text
http://127.0.0.1:5173
```

Credenziali demo:

```text
doctor@example.test
password-demo
```

## Build di verifica

```powershell
cd Dashboard
npm run build
```

Output atteso:

```text
dist/
```

`dist/` e `node_modules/` sono ignorati da Git.

## Test scenari E2

Prima di avviare il mock:

```powershell
$env:MOCK_SCENARIO = "normal"
```

Oppure:

```powershell
$env:MOCK_SCENARIO = "severe_alert"
$env:MOCK_SCENARIO = "technical_issue"
$env:MOCK_SCENARIO = "missing_data"
```

La dashboard deve cambiare contenuto senza cambiare codice.
