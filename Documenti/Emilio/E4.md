# E4 - Overview e lista pazienti

Questo documento riassume il lavoro fatto per il punto E4: migliorare la dashboard
medico con una overview dei pazienti e una lista pazienti ordinabile, filtrabile e
coerente con i contratti che Daniel usera' nel backend reale.

## Obiettivo

La dashboard deve permettere al medico di capire rapidamente:

```text
quali pazienti sono monitorati
quali pazienti hanno priorita clinico-comportamentale
quali pazienti hanno problemi tecnici
quali dati sono obsoleti
quale paziente e' selezionato
```

La UI continua a usare linguaggio di triage e non presenta diagnosi automatiche.

## Cosa e' stato implementato

### Lista pazienti ordinabile

Nella sidebar della dashboard e' stata aggiunta una lista pazienti con ordinamento per:

```text
severita
ultimo aggiornamento
```

L'ordinamento per severita' mette prima i pazienti piu' critici:

```text
red
orange
yellow
technical
green
```

In caso di pari livello, viene usato l'ultimo aggiornamento.

### Filtri lista

Sono stati aggiunti filtri rapidi:

```text
Tutti
Comportamentali
Tecnici
Obsoleti
```

Quando si apre il dettaglio di un paziente, ordinamento e filtro non vengono azzerati.
Questo permette al medico di rimanere nello stesso contesto di lavoro.

### Semaforo completo

La lista supporta tutti i livelli previsti:

```text
green
yellow
orange
red
technical
```

Ogni riga mostra il colore del livello e un testo leggibile, cosi' il significato non
dipende solo dal colore.

### Dati operativi nella lista

Ogni paziente mostra:

```text
stanza corrente
presenza del watch
stato Edge/Raspberry
tipo di segnale
eventuale dato obsoleto
```

Il tipo di segnale separa:

```text
routine
segnale comportamentale
guasto tecnico
```

Questa distinzione e' importante per non confondere un'anomalia ADL con un problema di
raccolta dati, per esempio watch assente o Raspberry offline.

### Overview superiore

Nel workspace principale e' stata aggiunta una overview sintetica con:

```text
pazienti monitorati
pazienti ad alta priorita
problemi tecnici
dati obsoleti
paziente selezionato
```

La overview resta visibile sopra le viste Paziente, Alert, Task e Sistema.

### Mock backend aggiornato

Il mock backend ora restituisce piu' pazienti dimostrativi:

```text
patient-001 -> green / routine
patient-002 -> yellow / segnale comportamentale
patient-003 -> orange / segnale comportamentale
patient-004 -> red / segnale comportamentale
patient-005 -> technical / guasto tecnico
```

Gli endpoint di dettaglio funzionano per ciascun paziente:

```text
GET /api/v1/patients/{patient_id}/current
GET /api/v1/patients/{patient_id}/windows
GET /api/v1/patients/{patient_id}/decisions
GET /api/v1/patients/{patient_id}/alerts
GET /api/v1/patients/{patient_id}/tasks
GET /api/v1/patients/{patient_id}/system-status
WS  /ws/v1/patients/{patient_id}
```

Questa struttura resta compatibile con il futuro backend reale di Daniel: quando D5 e D6
saranno pronti, la dashboard dovra' cambiare soltanto URL nel file `.env`.

## Verifiche fatte

Compilazione Python del mock backend:

```powershell
python -m compileall mock_backend
```

Build della dashboard:

```powershell
cd Dashboard
npm run build
```

Verifica endpoint lista pazienti:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8090/api/v1/patients
```

Output atteso:

```text
5 pazienti con livelli green, yellow, orange, red e technical
```

Verifica dettaglio paziente:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8090/api/v1/patients/patient-004/current
Invoke-RestMethod -Uri http://127.0.0.1:8090/api/v1/patients/patient-005/system-status
```

## Come testare manualmente

Avviare il mock backend:

```powershell
cd mock_backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8090
```

Avviare la dashboard:

```powershell
cd Dashboard
npm run dev
```

Aprire:

```text
http://127.0.0.1:5173
```

Credenziali demo:

```text
doctor@example.test
password-demo
```

Test da fare:

- ordinare per severita';
- ordinare per ultimo aggiornamento;
- filtrare solo comportamentali;
- filtrare solo tecnici;
- filtrare solo obsoleti;
- aprire un paziente e verificare che il filtro resta impostato;
- selezionare `Paziente Tecnico` e verificare che venga mostrato come problema tecnico,
  non come anomalia comportamentale;
- selezionare `Paziente Priorita` e verificare alert e livello red.
