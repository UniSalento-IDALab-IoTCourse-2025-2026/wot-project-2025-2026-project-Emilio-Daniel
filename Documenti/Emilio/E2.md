# E2 - Mock backend per sviluppo frontend

Questo documento riassume il lavoro fatto per il punto E2: creare un backend mock locale
che permette di sviluppare dashboard medico, app paziente e caregiver anche quando il
backend Cloud reale di Daniel e' spento o non ancora completo.

## Obiettivo

Il mock deve esporre endpoint compatibili con il contratto API/WebSocket condiviso:

```text
Documenti/contracts/API_CONTRACT.md
```

In questo modo la dashboard potra' partire usando dati finti e, quando Daniel finisce le
API reali, cambiare soltanto gli URL nel file `.env`.

## Endpoint implementati

Il mock espone:

```text
GET    /health
GET    /ready
POST   /api/v1/auth/login
GET    /api/v1/patients
GET    /api/v1/patients/{patient_id}/current
GET    /api/v1/patients/{patient_id}/windows
GET    /api/v1/patients/{patient_id}/decisions
GET    /api/v1/patients/{patient_id}/alerts
PATCH  /api/v1/alerts/{alert_id}/acknowledge
PATCH  /api/v1/alerts/{alert_id}/resolve
POST   /api/v1/patients/{patient_id}/tasks
GET    /api/v1/patients/{patient_id}/tasks
POST   /api/v1/tasks/{task_id}/results
POST   /api/v1/devices/push-token
POST   /api/v1/patients/{patient_id}/app-status
GET    /api/v1/patients/{patient_id}/system-status
WS     /ws/v1/patients/{patient_id}
```

Questi endpoint seguono il contratto definito con Daniel: base path `/api/v1`, liste
paginabili, valori mancanti come `null`, errori in formato stabile e WebSocket con
`event_type`, `event_id`, `patient_id`, `timestamp` e `payload`.

## Scenari simulati

Il mock supporta quattro scenari:

```text
normal
severe_alert
technical_issue
missing_data
```

### normal

Paziente stabile, livello `green`, Edge online, Watch presente, BLE attivo, nessun alert.

### severe_alert

Paziente con livello `red`, `should_publish=true`, alert comportamentale severo e score
alto. Serve per sviluppare lista alert, dettaglio alert, presa in carico e notifiche.

### technical_issue

Problema tecnico separato dalla parte clinica: wearable mancante o batteria critica,
qualita' dati in warning e coda MQTT non vuota. Serve per visualizzare guasti tecnici
senza confonderli con diagnosi o allarmi clinici.

### missing_data

Alcune feature wearable sono `null`, ad esempio battito, passi o batteria. Serve per
verificare che la dashboard non interpreti i dati mancanti come zero.

## Configurazione

File:

```text
mock_backend/.env.example
```

Variabili:

```text
MOCK_SCENARIO=normal
MOCK_WS_INTERVAL_SECONDS=5
```

Esempio Windows:

```powershell
$env:MOCK_SCENARIO = "severe_alert"
$env:MOCK_WS_INTERVAL_SECONDS = "3"
```

Esempio Raspberry/Linux/macOS:

```bash
export MOCK_SCENARIO=severe_alert
export MOCK_WS_INTERVAL_SECONDS=3
```

## Avvio

Da root progetto:

```powershell
cd mock_backend
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8090
```

URL utili:

```text
http://127.0.0.1:8090/health
http://127.0.0.1:8090/docs
http://127.0.0.1:8090/api/v1/patients
http://127.0.0.1:8090/api/v1/patients/patient-001/current
ws://127.0.0.1:8090/ws/v1/patients/patient-001
```

## Config per dashboard

File preparato:

```text
mock_backend/dashboard.env.example
```

Contenuto:

```text
VITE_API_BASE_URL=http://127.0.0.1:8090/api/v1
VITE_WS_BASE_URL=ws://127.0.0.1:8090/ws/v1
VITE_DATA_SOURCE=mock
```

Quando creeremo la dashboard React, copieremo questi valori nel suo `.env`. Per passare
al backend reale di Daniel bastera' cambiare:

```text
VITE_API_BASE_URL=http://host-backend-reale/api/v1
VITE_WS_BASE_URL=ws://host-backend-reale/ws/v1
VITE_DATA_SOURCE=real
```

## WebSocket

Il mock invia eventi periodici su:

```text
ws://127.0.0.1:8090/ws/v1/patients/patient-001
```

Eventi simulati:

```text
system_status_updated
decision_updated
alert_created
```

`alert_created` compare negli scenari `severe_alert` e `technical_issue`.

## Test

Compilazione:

```powershell
python -m compileall mock_backend
```

Test automatici, dopo aver installato le dipendenze del mock:

```powershell
cd mock_backend
.\.venv\Scripts\python -m pytest tests
```

Test manuale veloce:

```powershell
Invoke-RestMethod http://127.0.0.1:8090/health
Invoke-RestMethod http://127.0.0.1:8090/api/v1/patients/patient-001/current
```

## Privacy

Il mock contiene solo dati dimostrativi:

```text
patient-001
Paziente Demo
Dr. Rossi
```

Non sono presenti dati personali reali, token Google Health, password, certificati,
refresh token o informazioni cliniche vere.
