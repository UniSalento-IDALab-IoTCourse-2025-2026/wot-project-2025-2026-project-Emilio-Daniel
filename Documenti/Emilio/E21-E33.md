## Endpoint usati quando disponibili

```text
GET  /api/v1/patients/{patient_id}/ai/model-metrics
GET  /api/v1/patients/{patient_id}/day-profile
GET  /api/v1/patients/{patient_id}/reports/weekly
GET  /api/v1/patients/{patient_id}/morning-brief
POST /api/v1/patients/{patient_id}/ai/retraining/approve
GET  /api/v1/metrics
```

Se un endpoint non esiste ancora, la chiamata viene trattata come opzionale e la dashboard
usa i dati gia' disponibili: `current`, `windows`, `decisions`, `alerts`, `tasks`,
`summary24h`, `timeline`, `spatialSummary` e `reportData`.

## Test da provare

```powershell
cd Dashboard
npm test
npm run build
```

Test manuale rapido:

- avvia backend e dashboard;
- entra come medico;
- apri `patient-001`;
- verifica "Brief del mattino";
- apri "Valutazione comportamentale" e controlla confidenza, affidabilita' modello, trend;
- apri "Giornata tipo" e cambia metrica;
- apri "Stato sistema" e premi "Diagnostica rapida";
- spegni temporaneamente il backend e ricarica: deve comparire la cache offline;
- prova a creare un task in offline: i comandi devono risultare bloccati.
