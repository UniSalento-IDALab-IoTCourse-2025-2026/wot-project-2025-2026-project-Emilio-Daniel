# E5 - Pagina alert e presa in carico

Questo documento riassume il lavoro fatto per il punto E5: rendere la pagina Alert
della dashboard medico utilizzabile per triage, presa in carico, risoluzione e
creazione di task collegati al paziente.

## Obiettivo

La pagina Alert deve permettere al medico di:

```text
vedere gli alert aperti o recenti
capire livello, score, timestamp, stato e motivi
filtrare gli alert per priorita, stato e intervallo temporale
prendere in carico un alert con conferma
risolvere un alert solo inserendo una nota
vedere chi ha preso in carico o risolto l'alert
creare un task di follow-up direttamente dall'alert
```

La schermata resta sempre una schermata di triage: non produce diagnosi automatiche.

## Cosa e' stato implementato

### Dettaglio alert

Ogni alert mostra in modo strutturato:

```text
timestamp di apertura
livello semaforico
score di anomalia
categoria dell'alert
stato dell'alert
titolo e descrizione
motivi principali
utente che ha preso in carico
timestamp di presa in carico
utente che ha risolto
timestamp di risoluzione
```

I livelli supportati sono:

```text
yellow
orange
red
technical
```

Gli stati supportati sono:

```text
new
acknowledged
resolved
```

### Filtri

Sono stati aggiunti tre filtri:

```text
livello
stato
intervallo temporale
```

Gli intervalli disponibili sono:

```text
tutto
ultime 24 ore
ultimi 7 giorni
```

Questo permette al medico di concentrarsi sugli alert piu' urgenti o su quelli ancora
non gestiti.

### Presa in carico

Il pulsante `Prendi in carico`:

```text
chiede conferma prima di procedere
chiama PATCH /api/v1/alerts/{alert_id}/acknowledge
aggiorna la vista dopo la risposta del backend
mostra chi ha preso in carico l'alert e quando
```

Nel mock backend questa informazione resta in memoria finche' il server mock resta
acceso.

### Risoluzione alert

Il pulsante `Risolvi`:

```text
richiede una nota obbligatoria
chiede conferma prima di procedere
chiama PATCH /api/v1/alerts/{alert_id}/resolve
aggiorna la vista dopo la risposta del backend
mostra chi ha risolto l'alert e quando
```

Se la nota e' vuota, la dashboard blocca l'azione prima ancora di inviare la richiesta.
Anche il mock backend mantiene il controllo lato API e ritorna errore se la nota manca.

### Aggiornamento realtime

La dashboard ora ricarica i dati del paziente quando arrivano eventi WebSocket di tipo:

```text
decision_updated
alert_created
alert_acknowledged
alert_resolved
task_created
system_status_updated
```

Il mock backend genera `alert_acknowledged` e `alert_resolved` quando lo stato dell'alert
viene modificato. Questa scelta resta coerente con il futuro backend reale di Daniel.

### Creazione task dal dettaglio alert

Dal singolo alert e' possibile creare un task di follow-up per il paziente.

Il task usa:

```text
type = alert_follow_up
priority coerente con il livello dell'alert
payload con alert_id, livello, categoria, stato e score sorgente
```

Questo permette di collegare un alert a un'azione operativa successiva, per esempio un
check-in, una verifica clinica o una richiesta al caregiver.

### Mock backend aggiornato

Il mock backend ora salva in memoria:

```text
stato acknowledged
acknowledged_at
acknowledged_by
stato resolved
resolved_at
resolved_by
resolution_note
```

Gli endpoint interessati sono:

```text
GET   /api/v1/patients/{patient_id}/alerts
PATCH /api/v1/alerts/{alert_id}/acknowledge
PATCH /api/v1/alerts/{alert_id}/resolve
POST  /api/v1/patients/{patient_id}/tasks
WS    /ws/v1/patients/{patient_id}
```

## Come testare manualmente

Avviare il mock backend:

```powershell
cd mock_backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8090
```

Avviare la dashboard:

```powershell
cd Dashboard
npm run dev
```

Aprire:

```text
http://127.0.0.1:5173
```

Credenziali locali:

```text
Usare email e password configurate nel .env locale del backend.
```

Test da fare:

- selezionare `Paziente Priorita`;
- aprire la scheda `Alert`;
- verificare timestamp, livello, score, motivi e stato;
- filtrare per `red`;
- filtrare per `Nuovi`;
- premere `Prendi in carico` e confermare;
- verificare che compaiano utente e timestamp di presa in carico;
- provare `Risolvi` senza nota e verificare che venga bloccato;
- inserire una nota e risolvere l'alert;
- filtrare per `Risolti`;
- premere `Crea task`;
- aprire la scheda `Task` e verificare la presenza del task di follow-up.
