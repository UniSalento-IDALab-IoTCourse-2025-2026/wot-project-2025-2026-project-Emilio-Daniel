# E1 - Publisher MQTT sul Raspberry Pi 5

Questo documento riassume il lavoro fatto per il punto E1: pubblicare dal Raspberry Pi 5
gli output dell'Edge Node verso il broker MQTT configurato da Daniel, senza fermare il
funzionamento locale del sistema.

## Obiettivo

Il Raspberry deve continuare a produrre localmente:

```text
outputs/last-cycle.json
data/processed/latest_window.csv
outputs/patient-001-decision.json
```

In piu', quando il broker MQTT e' raggiungibile, deve pubblicare gli stessi dati verso il
Cloud. Se il broker o Internet non sono disponibili, i messaggi devono restare in coda
locale e il ciclo Edge da 4 minuti deve continuare.

## Configurazione

La sezione nuova e':

```yaml
mqtt:
  enabled: true
  host: localhost
  port: 8883
  use_tls: true
  username: edge_patient_001
  password: ""
  password_env: MQTT_EDGE_PASSWORD
  client_id: edge-rpi5-001
  edge_id: edge-rpi5-001
  ca_file: ../cloud/mqtt/certs/ca.crt
  keepalive_seconds: 60
  connect_timeout_seconds: 8
  publish_timeout_seconds: 8
  queue_dir: data/state/mqtt_queue
  max_flush_messages: 50
  retain_status: true
```

Nel file versionato `edge.example.yml` MQTT resta disattivato. Sul Raspberry o sul PC di
test bisogna abilitarlo nel file locale `edge_node/config/edge.yml`, che e' ignorato da
Git.

La password non deve essere scritta nei documenti o nei log. In locale si imposta cosi':

```powershell
$env:MQTT_EDGE_PASSWORD = "password-edge"
```

Sul Raspberry:

```bash
export MQTT_EDGE_PASSWORD='password-edge'
```

## Topic pubblicati

Il publisher e' coerente con D4 di Daniel.

```text
iot/patients/patient-001/edge/status
iot/patients/patient-001/telemetry/window
iot/patients/patient-001/telemetry/decision
iot/patients/patient-001/alerts/critical
```

`alerts/critical` viene pubblicato solo quando la decisione AI contiene:

```json
{
  "should_publish": true
}
```

Quindi un semplice livello `yellow` o un'anomalia non confermata non genera alert critico
verso il Cloud.

## Formato messaggi

Ogni messaggio usa la busta richiesta dal backend:

```json
{
  "schema_version": 1,
  "message_id": "decision_updated-uuid",
  "event_type": "decision_updated",
  "patient_id": "patient-001",
  "edge_id": "edge-rpi5-001",
  "timestamp": "2026-07-11T10:00:00Z",
  "payload": {}
}
```

Regole implementate:

- `message_id` e' generato automaticamente ed e' univoco.
- `timestamp` e' sempre UTC.
- `patient_id` arriva dalla configurazione Edge.
- `edge_id` arriva dalla configurazione MQTT.
- I valori `nan` del CSV vengono convertiti in `null`.
- QoS e' `1` per status, finestre, decisioni e alert.
- `edge/status` puo' essere retained per rappresentare lo stato corrente.
- Telemetria, decisioni e alert non sono retained.

## Coda offline

La coda locale e':

```text
edge_node/data/state/mqtt_queue/
```

Se connessione, TLS, password o broker falliscono:

```text
messaggi del ciclo -> file JSON in data/state/mqtt_queue
```

Al ciclo successivo:

```text
prima svuota la coda in ordine FIFO
poi pubblica i messaggi nuovi
```

Questo evita che MQTT blocchi:

- receiver BLE;
- aggregazione Google Health/BLE;
- baseline;
- inferenza AI;
- salvataggio dei file locali.

## Last Will

Il publisher configura un Last Will su:

```text
iot/patients/patient-001/edge/status
```

Se il Raspberry cade senza disconnessione pulita, il broker pubblica:

```json
{
  "event_type": "edge_offline_unexpected",
  "payload": {
    "online": false,
    "reason": "mqtt_last_will"
  }
}
```

## Comando unico

Il publisher e' integrato nel comando gia' usato per avviare il sistema:

```powershell
.\Script\avvio\avviaSistema.ps1
```

Su Raspberry:

```bash
./Script/avvio/avviaSistema
```

Il comando avvia:

```text
receiver Android BLE
runtime Edge ogni 4 minuti
baseline automatica
publisher MQTT se mqtt.enabled=true
```

## Test senza broker

Da `edge_node/`:

```powershell
python -m edge_mqtt.cli --config config/edge.yml --dry-run
```

Questo stampa i messaggi MQTT che verrebbero inviati, senza connettersi al broker.

Test unitari:

```powershell
python -m pytest tests/test_edge_mqtt.py
```

Questi test controllano:

- conversione `latest_window.csv` in JSON;
- conversione `nan` in `null`;
- creazione alert solo con `should_publish=true`;
- scrittura e rilettura della coda locale.

Quando MQTT e backend D4 sono accesi:

```powershell
cd cloud

```

Poi Daniel avvia il worker:

```powershell
cd cloud\backend
.\.venv\Scripts\python -m alembic upgrade head
.\.venv\Scripts\python -m app.mqtt.worker
```

Noi avviamo il sistema Edge:

```powershell
$env:MQTT_EDGE_PASSWORD = "password-edge"
.\Script\avvio\avviaSistema.ps1
```

Verifiche:

```text
1. outputs/last-cycle.json contiene mqtt_publish.status = published
2. data/state/mqtt_queue resta vuota se il broker e' raggiungibile
3. PostgreSQL riceve righe in feature_windows e decisions
4. alerts riceve righe solo con should_publish=true
5. se si spegne il broker, i messaggi finiscono in data/state/mqtt_queue
6. quando il broker torna online, la coda si svuota automaticamente
```
