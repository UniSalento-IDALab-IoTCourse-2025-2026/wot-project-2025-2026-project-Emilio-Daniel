# D11 - Stato sistema e integrazione Google Health

## Obiettivo

D11 rende piu' affidabile lo stato tecnico esposto dal backend alla dashboard medico.

Il punto non e' diagnosticare il paziente, ma distinguere chiaramente:

```text
problema clinico/comportamentale
vs
problema tecnico o dati non aggiornati
```

L'endpoint principale resta:

```text
GET /api/v1/patients/{patient_id}/system-status
```

## Cosa abbiamo completato

- Il backend espone feature Google Health disponibili nell'ultima finestra.
- Gli errori OAuth/Google Health vengono ripuliti prima di essere mandati alla dashboard.
- Refresh token, access token, password, client secret e header Authorization non vengono
  mai esposti.
- Lo stato del Raspberry viene calcolato usando ultimo ciclo/heartbeat e soglia stale.
- Lo stato di watch, BLE, Google Health e app paziente viene calcolato con soglie
  configurabili.
- Lo stato app paziente espone device, piattaforma, versione app, batteria, notifiche e
  presenza token FCM senza mostrare il token.

## Soglie configurabili

Le soglie sono nel file:

```text
cloud/backend/.env
```

Valori di default:

```env
IOT_BACKEND_EDGE_STALE_MINUTES=10
IOT_BACKEND_WATCH_STALE_MINUTES=12
IOT_BACKEND_BLE_STALE_MINUTES=12
IOT_BACKEND_GOOGLE_HEALTH_STALE_MINUTES=12
IOT_BACKEND_PATIENT_APP_STALE_MINUTES=15
```

Queste soglie permettono alla dashboard di mostrare `active`, `stale`, `missing`,
`offline`, `disabled` o `error` in modo coerente.

## Google Health

Google Health viene considerato:

- `disabled`: sorgente non abilitata dall'Edge;
- `error`: presente errore OAuth o errore Google Health ripulito;
- `active`: ci sono feature disponibili e la finestra e' recente;
- `stale`: dati disponibili ma troppo vecchi, oppure nessuna feature recente.

Le feature disponibili arrivano dall'ultimo ciclo Edge o, come fallback, dalle feature
presenti nell'ultima finestra.

## App paziente

Il backend usa `patient_app_status` per calcolare lo stato dell'app companion:

- `active`: heartbeat recente;
- `stale`: device registrato ma non aggiornato da troppo tempo;
- `missing`: nessun device registrato.

Il payload espone solo dati tecnici utili:

```json
{
  "status": "active",
  "device_id": "android-...",
  "platform": "android",
  "app_version": "0.3.0",
  "battery_pct": 73,
  "notifications_enabled": true,
  "fcm_registered": true
}
```

Il token FCM non viene mai restituito.
