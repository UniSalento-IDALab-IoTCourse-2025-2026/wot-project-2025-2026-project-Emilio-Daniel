# D2 - Struttura Backend FastAPI

Questo documento riassume il punto D2 della scaletta di Daniel: creazione dello scheletro
del backend Cloud FastAPI.

## Obiettivo

Creare un backend unico e modulare che fara' da centro tra:

```text
MQTT broker -> backend -> database -> dashboard medico / app paziente / caregiver
```

In D2 non colleghiamo ancora PostgreSQL e MQTT reali. Prepariamo pero' la struttura stabile
che verra' usata nei punti successivi.

## Scelta fatta

Abbiamo scelto:

```text
FastAPI backend unico, non microservizi separati
```

Motivi:

- il progetto e' ancora in prima versione;
- un unico backend e' piu' semplice da avviare, testare e debuggare;
- separiamo comunque i moduli internamente;
- in futuro si potra' dividere in microservizi solo se serve davvero.

## Configurazione

La configurazione usa variabili ambiente con prefisso:

```text
IOT_BACKEND_
```

Esempi:

```powershell
$env:IOT_BACKEND_ENVIRONMENT = "development"
$env:IOT_BACKEND_LOG_LEVEL = "INFO"
$env:IOT_BACKEND_MQTT_HOST = "localhost"
$env:IOT_BACKEND_MQTT_PORT = "8883"
$env:IOT_BACKEND_MQTT_USE_TLS = "true"
```

Il file principale e':

```text
cloud/backend/app/core/config.py
```

La configurazione viene validata con Pydantic Settings.

## Errori

Gli errori hanno forma stabile:

```json
{
  "error": {
    "code": "http_error",
    "message": "Not Found",
    "details": {}
  }
}
```

Questo formato sara' usato dalla dashboard e dall'app per mostrare errori coerenti.

## Log

I log sono configurati in:

```text
cloud/backend/app/core/logging.py
```

Regola: nei log non vanno scritti token, password, refresh token Google Health, token FCM
o payload sanitari completi.
