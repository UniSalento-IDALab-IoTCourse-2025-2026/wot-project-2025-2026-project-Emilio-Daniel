# D14 - Endpoint timeline normalizzata

Questo documento riassume il lavoro fatto per il punto D14 della scaletta di Daniel.
L'obiettivo e' fornire alla dashboard una timeline unica del paziente, evitando che il
frontend debba unire manualmente finestre, decisioni AI, alert, task, notifiche e stati
tecnici.

## Endpoint aggiunto

```text
GET /api/v1/patients/{patient_id}/timeline
```

L'endpoint richiede autenticazione e usa le stesse regole di autorizzazione degli altri
endpoint paziente. Un utente puo' leggere la timeline solo se e' associato al paziente.

## Filtri supportati

```text
event_type
date_from
date_to
page
page_size
```

`event_type` puo' essere singolo oppure multiplo separato da virgola:

```text
GET /api/v1/patients/patient-001/timeline?event_type=decision_updated,alert_created
```

## Formato comune

Ogni evento viene restituito con gli stessi campi:

```json
{
  "event_id": "decision-12",
  "event_type": "decision_updated",
  "timestamp": "2026-07-15T10:00:00Z",
  "title": "Decisione AI rischio",
  "summary": "Score 74.5",
  "severity": "orange",
  "source": "ai",
  "linked_resource": {
    "type": "decision",
    "id": "decision-12",
    "message_id": "decision-message-id"
  }
}
```

Il frontend puo' quindi mostrare una timeline unica senza conoscere la struttura interna
di ogni tabella.

## Eventi inclusi

La timeline include:

- `patient_window_updated`: finestra dati Edge;
- `decision_updated`: decisione AI;
- `alert_created`: alert creato;
- `alert_acknowledged`: presa in carico alert;
- `alert_resolved`: risoluzione alert;
- `task_created`: task o test inviato;
- `task_seen`, `task_started`, `task_completed`: stati del task quando disponibili;
- `task_result_received`: risultato ricevuto dall'app paziente;
- `patient_message_created`: messaggio inviato al paziente;
- `caregiver_message_created`: messaggio inviato al caregiver;
- `edge_cycle_completed`: ciclo Edge;
- `sensor_{tipo}_updated`: stato tecnico sensore.

## Deduplicazione

Quando un evento deriva da un messaggio tecnico con `message_id`, il backend usa una
chiave interna di deduplicazione. Questo evita duplicati visivi se lo stesso messaggio
viene ritrasmesso o riletto.

La deduplicazione non elimina eventi clinicamente diversi: ad esempio un alert creato e
un alert risolto restano due eventi separati.

## Sicurezza

La timeline non espone:

- token FCM;
- password;
- refresh token;
- dettagli OAuth;
- payload tecnici non necessari.

Gli eventi rimandano alle risorse tramite `linked_resource`, ma non copiano dati sensibili
nel payload timeline.
