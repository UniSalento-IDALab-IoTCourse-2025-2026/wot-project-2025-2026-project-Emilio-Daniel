# D15 - Backend per questionari programmabili e storico punteggi

## Obiettivo

Rendere i questionari una risorsa stabile del backend, invece di trattarli come semplici
payload liberi dentro un task. In questo modo la dashboard puo' mostrare un centro
valutazioni ordinato, programmare check-in ripetibili e leggere uno storico punteggi
coerente.

## Cosa e' stato aggiunto

### Modelli database

Sono state aggiunte due nuove tabelle:

```text
questionnaire_templates
questionnaire_schedules
```

`questionnaire_templates` contiene la definizione del questionario:

- chiave del template, ad esempio `daily_checkin`;
- versione;
- titolo e descrizione;
- tipo task generato, normalmente `check_in`;
- domande strutturate;
- regole di scoring;
- priorita' predefinita;
- stato attivo/non attivo.

`questionnaire_schedules` contiene la programmazione per uno specifico paziente:

- paziente;
- template usato;
- frequenza `daily` o `weekly`;
- prossima esecuzione;
- ultimo task generato;
- stato `active`, `suspended` o `completed`;
- override opzionali di titolo, istruzioni, priorita' e payload.

La migrazione e':

```text
cloud/backend/alembic/versions/20260716_0005_questionnaires.py
```

## Endpoint aggiunti

Base:

```text
/api/v1/questionnaires
```

Endpoint principali:

```text
GET   /api/v1/questionnaires/status
GET   /api/v1/questionnaires/templates
POST  /api/v1/questionnaires/templates
GET   /api/v1/questionnaires/patients/{patient_id}/schedules
POST  /api/v1/questionnaires/patients/{patient_id}/schedules
PATCH /api/v1/questionnaires/schedules/{schedule_id}/suspend
POST  /api/v1/questionnaires/schedules/{schedule_id}/generate-due-task
GET   /api/v1/questionnaires/patients/{patient_id}/results
```

## Perche' la generazione e' via endpoint

Per ora non e' stato aggiunto un worker automatico separato. La generazione del task
programmato avviene tramite:

```text
POST /api/v1/questionnaires/schedules/{schedule_id}/generate-due-task
```

Motivo: cosi' la funzionalita' e' testabile subito, senza introdurre un servizio
background aggiuntivo prima di aver completato il deployment finale. In produzione si
potra' richiamare lo stesso endpoint o la stessa logica da un job pianificato.

Il backend evita duplicati: se una programmazione giornaliera ha gia' generato un task
nello stesso giorno, la seconda richiesta restituisce `already_generated` con il task
esistente.

## Esempio template

```json
{
  "template_key": "daily_checkin",
  "title": "Check-in quotidiano",
  "description": "Breve controllo sullo stato percepito.",
  "task_type": "check_in",
  "questions": [
    {
      "id": "mood",
      "type": "scale",
      "text": "Come ti senti oggi?",
      "min": 0,
      "max": 10
    },
    {
      "id": "dizziness",
      "type": "yes_no",
      "text": "Hai avuto capogiri?"
    }
  ],
  "scoring": {
    "type": "scale_average",
    "question_ids": ["mood"]
  }
}
```
