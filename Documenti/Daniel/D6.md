# D6 - WebSocket realtime

Questo documento riassume il lavoro fatto per il punto D6 della scaletta di Daniel:
abilitare aggiornamenti realtime dal backend reale verso la dashboard medico.

## Obiettivo

La dashboard deve potersi collegare a:

```text
WS /ws/v1/patients/{patient_id}
```

Quando cambiano dati del paziente, il backend invia un evento con:

```json
{
  "event_type": "decision_updated",
  "event_id": "event-...",
  "patient_id": "patient-001",
  "timestamp": "2026-07-12T10:00:00Z",
  "payload": {}
}
```

La dashboard usa questi eventi per ricaricare via REST i dati aggiornati.

## Eventi supportati

Il backend puo' inviare:

```text
system_status_updated
decision_updated
alert_created
alert_acknowledged
alert_resolved
task_created
task_completed
```

## Come funziona

D6 usa due sorgenti:

1. Eventi in memoria prodotti dallo stesso processo FastAPI.
2. Polling leggero del database per intercettare anche i dati salvati dal worker MQTT.

Questo e' importante perche' il worker MQTT D4 puo' girare in un processo separato da
Uvicorn. Un event bus solo in memoria non basterebbe per vedere subito i messaggi MQTT
salvati in PostgreSQL.

Flusso:

```text
MQTT worker salva finestra/decisione/alert nel DB
-> WebSocket vede il cambio nella snapshot del paziente
-> invia evento alla dashboard
-> dashboard ricarica REST /current, /alerts, /tasks, ecc.
```

Per azioni REST fatte nello stesso backend, come `acknowledge`, `resolve`, creazione task
e completamento task, il backend pubblica anche un evento in memoria immediato.
